## Доступ к raspberrypi для Claude Code

Claude Code МОЖЕТ без дополнительного разрешения в каждом отдельном случае:
- Заходить на raspberrypi по SSH (`ssh raspberrypi`) с любой разрешённой машины
  (Mac mini и т.п.)
- Запускать там read-only Python-скрипты, использующие УЖЕ СУЩЕСТВУЮЩИЙ `.env` этой
  машины через её собственный python-dotenv/venv — по образцу существующих скриптов
  проекта (`get_candles`, список инструментов через `client.instruments`, чтение логов,
  чтение CSV-файлов состояния для АНАЛИЗА/ОТЧЁТНОСТИ)
- Копировать через rsync исторические данные (`out/`, `data_cache/candles/`, `universe.csv`
  и т.п.) на другие машины

Claude Code НИКОГДА не делает без явного отдельного разрешения человека в моменте, даже если формально технически возможно:
- Не размещает ордера (не вызывает `orders.post_order` / любой метод, приводящий к
  реальной сделке)
- Не читает и не выводит в любом виде (в чат, в лог, в файл) само значение
  `TINKOFF_TOKEN` или другого секрета из `.env` — только использует его косвенно через
  существующий код той машины, никогда не печатает
- Не изменяет `orders/`, `.state/`, `state/`, `pending_stops.csv` на raspberrypi
- Не меняет crontab и systemd unit-файлы на raspberrypi
- Не устанавливает `AUTO_EXECUTE_ENABLED`/`ALLOW_PLACE` и не трогает любые флаги
  реального исполнения

Если задача выходит за эти рамки — Claude Code останавливается и спрашивает явно, как делал раньше.

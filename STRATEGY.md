# Стратегия автоматизированной торговли

## 1. Ежедневный отбор вселенной (universe_builder.py, ~07:10 МСК)
- Ликвидность: средний дневной оборот ≥ 10 млн ₽
- Исключать инструмент, если дивидендная отсечка или публикация отчётности в пределах ±7 дней
- LONG: акции и фьючерсы допустимы. SHORT: только фьючерсы (не шортить акции напрямую)
- Исключать инструменты с комиссией за сделку выше 0.5% (50 bps)

## 2. Внутридневной анализ и вход (scan_live_full.py, каждые 15 мин, 10:00-18:00 МСК)
- Индикаторы RSI D1/H4, volume_ratio, паттерны — уже реализованы
- AI-фильтр (ai_filter_agent.py) — уже работает
- ТРЕБУЕТСЯ: автоматический вызов trade_executor.py без Telegram/Sheets/человека
- Тип ордера (market/limit) выбирается автоматически по ситуации на рынке

## LLM-проверка сигналов (llm_signal_reviewer.py)

После ai_filter_agent.py (формальные правила на Python, без ИИ) добавляется
независимый второй барьер — llm_signal_reviewer.py:

- Берёт кандидатов, уже прошедших правила (decision=PASS/verdict=approve).
- Вызывает Claude API (модель claude-haiku-4-5-20251001) в роли количественного
  риск-ревьюера. Модель видит ТОЛЬКО уже посчитанные цифры: side, entry, stop,
  target, rsi_d1, rsi_h4, volume_ratio, pattern, risk:reward, score/reasons
  формальных правил. Поиск новостей и любые внешние знания о конкретном
  тикере не используются и не запрашиваются.
- Ответ модели — строго JSON: {"decision": "approve"/"reject", "reasoning": "..."}.
- При сбое вызова (таймаут ~15 сек, ошибка API, невалидный JSON в ответе) —
  decision=reject по умолчанию (безопасное поведение), в логе отдельно
  помечается, что это техническая ошибка, а не содержательный отказ модели.
- Все решения (approve и reject) логируются в logs/llm_review.log для аудита.
- auto_executor.py больше не читает candidates_ai.csv напрямую — он читает
  candidates_llm_approved.csv (выход этого шага), то есть вход в реальный
  ордер требует одобрения и правил, и LLM.

## 3. Стоп сразу при входе
- trade_executor.py должен сам сразу выставлять стоп-ордер после исполнения входа, 
  не дожидаясь отдельного периодического процесса

## 4. Риск-менеджмент
- Риск на сделку: RISK_PER_TRADE из .env (уже есть)
- Максимум 10 одновременно открытых позиций
- Дневной лимит убытка: 3% от капитала — при достижении новые входы блокируются 
  до конца торгового дня, существующие позиции остаются под защитой стопов

## 5. Журнал сделок
- Использовать существующую структуру orders/{pending,queue,executed,rejected} + logs/orders_log.csv
- Дополнительно: единый файл истории сделок с P&L для анализа результатов

## План реализации
1. Починить get_figi_by_ticker в scan_live_full.py (кэширование + futures())
2. Проверить/дополнить фильтры в universe_builder.py
3. Добавить проверку открытой позиции в trade_executor.py перед входом
4. Написать daily_risk_guard.py — трекер дневного P&L с флагом остановки при -3%
5. Написать auto_executor.py — автоматический мост candidates_ai.csv → trade_executor.py
6. Тестировать в --dry-run несколько дней
7. Включить в бой

Это боевой счёт (ALLOW_PLACE=true) — реальные деньги, действовать осторожно.
